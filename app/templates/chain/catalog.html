Blockchain

Three kinds of chain

A blockchain is an append-only log where each block commits to the one before it by hash. What differs between "blockchains" is who may append and how everyone agrees. These three working chains cover the main answers. Everything runs locally, is persisted in app_files/db/chain.db, and can be reset.

What all three share (the actual "blockchain" part)

  • Every hash is SHA-256 over canonical JSON (sorted keys, no whitespace) of exactly the fields that define the object. The original code hashed datetime.now() at verification time — so nothing could ever verify. Determinism is the whole game.
  • Transactions are content-addressed: the txid is the hash of the transaction. Change a digit and it is a different transaction with a different id.
  • A block header commits to its transactions through a Merkle root; each page can show the proof path for a single transaction.
  • Each header includes the previous block's hash. Editing block 5 changes its hash, which block 6 committed to, and so on to the tip — which is what "immutable" concretely means.
  • Verification is explicit and itemised: link, header hash, Merkle root, plus the consensus check (proof-of-work target or validator signature) and the rules of that chain (balances, UTXOs, coinbase amount).
