{{ notes.section('What you are seeing', [ 'A service worker is a script the browser runs between your page and the network, even when no tab is open. Every request in its scope passes through its fetch handler, which can answer from a cache, the network, or invent a response.', 'At install it precaches the "app shell" — this page and its CSS/JS. That is why the page reloads offline. The lines marked SW in the wire log are the worker telling the page which source it used.', 'cache-first: after the first call the clock never changes — you are reading a stored answer. network-first: fresh while online, falls back to the last good answer offline. stale-while-revalidate: the old answer instantly, and a fresh one lands in the cache for next time. network-only: honest, and dead offline.', 'Clear the cache and go offline: cache-first and network-first now fail too. A strategy is only as good as what has been cached.' ], 'accent') }} {{ notes.section('Choosing a strategy', [ 'Cache-first for things that never change under one URL: hashed assets (app.3f9a1c.js), fonts, icons.', 'Network-first for data that must be fresh when possible but where stale is better than nothing: articles, product pages, a timeline.', 'Stale-while-revalidate for data where instant matters more than perfectly current: avatars, feeds, config. It is what most "feels instant" apps do.', 'Network-only for anything that must never be stale or is not safe to cache: payments, auth, anything personal.', 'Libraries like Workbox package these strategies with routing and cache expiry so you do not hand-write the handler above.' ]) }} {{ notes.section('Gotchas', [ 'Scope is by URL path: a worker at /lab/sw.js can control /lab/… and below, never /tools.
