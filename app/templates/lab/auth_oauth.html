The happy path

You are on Compiled (the client). Clicking below redirects your browser to FakeID (the identity provider), also hosted here. You will see its consent screen, approve, and land on a results page that lists every step both sides took.

Break it on purpose

Evil redirect_uri Wrong PKCE verifier Reuse the code Forged callback
AttackWhat the attacker hopesWhat stops it
Evil redirect_uriThe IdP sends the code to a URL they controlIdP compares against the registered URI and refuses — without redirecting
Wrong verifierA stolen code is exchanged for tokensPKCE: SHA256(verifier) must equal the challenge sent at the start
Reuse the codeExchange the same code twiceCodes are one-shot; a second use also revokes the first tokens
Forged callbackTrick the client into finishing a flow it never startedstate must match a pending flow on the client

The dance

Browser                Client (Compiled)              IdP (FakeID)
  │  click "Log in"        │                              │
  │───────────────────────▶│ mint state, verifier          │
  │◀── 302 to /authorize ──│ store both, keyed by state    │
  │─────────────── GET /idp/authorize?client_id&redirect_uri&state&code_challenge ──▶│
  │◀────────────────────────────────────── consent page ───│
  │─────────────── POST /idp/approve  (Allow) ─────────────────────────────────────▶│
  │◀── 302 to /oauth/callback?code&state ─────────────────────────────────────────│
  │───────────────────────▶│ state matches? ✓              │
  │                        │── POST /idp/token {code, verifier, client_secret} ──▶│
  │                        │◀── {access_token, id_token} ──────────────────────────│
  │                        │ verify id_token: sig, exp, aud, nonce                  │
  │                        │── GET /idp/userinfo  Bearer ──────────────────────────▶│
  │◀── logged-in page ─────│◀── {sub, name, email} ────────────────────────────────│
