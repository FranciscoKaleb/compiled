{{ notes.section('What you are seeing', [ 'The QR code encodes an otpauth://totp/…?secret=…&issuer=… URI. The app stores the secret and from then on both sides can compute the same six digits from the same clock — nothing is ever sent between them again.', 'The code is HMAC-SHA1(secret, floor(unix_time / 30)), truncated to 31 bits, mod 10⁶. The counter row is that floor; the bar is how long the current window has left.', '"Fill in the previous code" still verifies: the server accepts one 30-second step either way, because phones drift. Verify it a second time and it fails — each window is one-shot, so a code overheard once cannot be replayed.', 'The secret is base32 because the earliest authenticator apps needed something a human could type when the camera failed.' ], 'accent') }} {{ notes.section('Where it sits', [ 'TOTP is the second factor: something you have (the phone with the secret) alongside something you know (the password). It stops password-only attacks — credential stuffing, leaked databases.', 'It is standardised (RFC 6238, built on HOTP RFC 4226), which is why any app works with any site. SMS codes are the weaker cousin: interceptable, SIM-swappable, and not a standard.', 'The stronger successors are WebAuthn / passkeys: public-key challenge–response bound to the origin, so phishing sites cannot relay them. TOTP codes can be phished in real time — an attacker page that proxies your code within 30 seconds wins.' ]) }} {{ notes.section('Gotchas', [ 'Store the secret encrypted at rest and treat it like a password. Anyone with it can generate every future code.', 'Track the last-used counter per user and refuse repeats — replay protection is your job, not the algorithm\'s.', 'Rate-limit verification attempts. Six digits is a million possibilities; with a ±1 window and no limit, brute force is a weekend.', 'Keep server clocks on NTP. Drift beyond the tolerance window looks to users like "the app is broken", and widening the window weakens replay protection.', 'Offer recovery codes at enrolment and make users confirm one valid code before enabling 2FA — otherwise a mis-scanned QR locks them out.' ], 'warn') }}
